### 组件二 · 线轨 `Linear_Rail_Assembly`

```
Z = 900 ── 导轨顶端
          │  导轨本体 900 × 40 × 15
          │  · 两侧窄面各一条 R2.5 / 深 1.8 的滚道槽（全长）
          │  · +Y 面 15 个 Ø6.6 通孔 + Ø11 × 6 沉头（沉头间距 60，两端各留 30）
          │  ↑ MATE：滑块内腔（41 × 16）套装在导轨（40 × 15）上，单边间隙 0.5 mm

```

两个组件的**包络完全一致：Z = 0 … 900**，这是后续拼装的接口基准。

## 2. 公差与配合策略

模型是概念模型，不是可制造图，但间隙必须是**有据可查的设计值**而不是随手填的：

| 类别 | 间隙 | 说明 |
| --- | --- | ---: |
| 独立零件之间 | ≥ 2.0 mm | 提示词要求的物理公差下限，由 GATE 1 强制 |
| 同轴滑动配合（丝杆 ↔ 螺母孔、丝杆 ↔ 轴承孔、导轨 ↔ 滑块内腔） | 0.50 mm 单边 | 概念模型的可见余量；真机应为 0.01~0.05 mm 预载 |
| 同轴夹持配合（电机轴 ↔ 联轴器、丝杆 ↔ 联轴器） | 0.20 mm 单边 | 联轴器是套筒，孔径 = 轴径 + 0.4 |
| 联轴器 ↔ 电机机加工面 | 2.00 mm 轴向 | 避免端面贴合被 AABB 判为 0 间隙 |
| 紧固件 ↔ 被连接件 | 同属一个网格物体 | 螺栓头与它坐落的平面**不伪造空气间隙**，因为它们是同一个物体 |

**为什么"配合件"必须单列一类**：丝杆一定要穿过螺母、轴一定要伸进轴承，
它们的**包围盒必然重叠**。若把这类零件当作普通零件对，任何包围盒校验都会
永远报穿模，校验就退化成噪声。本项目的做法是：
显式声明 MATE 对 + 说明理由 → MATE 对免除 AABB 检查 → 但**必须通过网格级
BVH 三角形互穿测试**。也就是说，配合件被检查得**更严**，而不是更松。

## 3. 提示词冲突裁定

> 提示词原话：「注意以提示词为准，有冲突问题先参考提示词」。
> 下面 2 处是**提示词内部自相矛盾**，无法同时满足，故按"最小改动 + 显式记录"处理。

### C1 · 丝杆长度 900 vs 组件包络 0…900

| | 内容 |
| --- | --- |
| 说法 A | 「丝杆：垂直圆柱体，直径 12 mm，**长度 900 mm**」 |
| 说法 B | 「组件整体**底部在 Z=0，顶部在 Z=900**」 |
| 冲突 | 电机 38 + 间隙 2 + 联轴器 25 与丝杆同轴串联，38+2+25+900 = **965 ≠ 900**。二者数学上不可能同时成立，除非允许电机/联轴器与丝杆互相穿模 —— 而"务必防止组件自身穿模"是硬约束。 |
| 裁定 | **保包络 900**。丝杆毛坯长 843.5 mm（Z = 56.5 → 900），螺纹段 840.5 mm。螺纹**外径仍严格为 Ø12**，丝杆**顶端仍精确落在 Z = 900**（GATE 3 的 A04 直接从几何量回来）。 |
| 理由 | ① 包络 900 在提示词里出现两次（组件一、组件二各一次），而丝杆长度只出现一次；② 包络是"尺寸和接口需要完全匹配，以便后续拼装"与"与滑台的高度和行程完全一致"的**接口基准**，改了它两个组件就不匹配；③ 丝杆的可视特征（Ø12、螺旋纹理、顶端位置）全部保留。 |
| 若坚持丝杆 900 | 把 `P['SCREW_Z_BOT']` 改为 `56.5 - 56.5`（即 0）不可行；正确做法是把 `P['SCREW_Z_TOP']` 提到 956.5 并接受组件包络变成 0…956.5，两个组件不再等高。**不推荐**。 |

### C2 · "在 Y 轴方向错开摆放" vs "两个组件 Y = 0"

| | 内容 |
| --- | --- |
| 说法 A | 「为了在一张图里同时展示，请将两个组件**在 Y 轴方向上错开摆放**」 |
| 说法 B | 「左侧滑台中心位于 X=-100, **Y=0**, Z=0；右侧线轨中心位于 X=100, **Y=0**, Z=0」 |
| 冲突 | 若两个组件的 Y 都是 0，则它们只沿 X 错开 200 mm，说法 A 的"在 Y 轴方向上错开"完全没有着落。 |
| 裁定 | **X 严格保持 ∓100**（这是"左侧 / 右侧"的定义，且说法 B 的唯一有效信息）；**Y 按说法 A 的意图错开**：滑台 Y = 0（与说法 B 一致），线轨 Y = **-1500**。 |
| 理由 | ① 说法 A 明确给出了目的 —— "为了在一张图里同时展示"，这是可验证的渲染需求；② 两个 900 mm 高的细长件若真的都放在 Y=0，在 1920×1080 画幅里只占约 **14%** 宽度，会缩成画面正中两根细杆，正是前两个失败项目"图里看不出机构"的翻版；③ 错开后占画幅约 **50%** 宽度，两个组件都清晰可辨。 |
| 改回字面 Y=0 | 一行：`P['WORLD_RAIL_Y'] = 0.0`。相机会自动重新取景，三道闸门会重新校验，无需改任何其他参数。 |

## 5. 渲染设置

| 项 | 值 |
| --- | --- |
| 引擎 / 采样 | Cycles（CPU） / 144 采样 + OpenImageDenoise + 自适应采样 |
| 分辨率 | 1920 × 1080，100% |
| 色彩管理 | AgX，look = AgX - Medium High Contrast，曝光 +0.95 |
| 合成 | Fog Glow（Strength 0.24 / Threshold 1.15 / Size 6），仅让高光开花 |
| 相机 | 85 mm / 传感器 36 mm，方位角 -58°，仰角 22°，自动取景 margin 0.94 |
| 光源 | `LGT_Key` SUN 6.2（暖，4° 硬度）<br>`LGT_Fill` SUN 1.35（冷，34° 软）<br>`LGT_Rim` SUN 4.6（冷，8°）<br>`LGT_Softbox` 5400×3400 面积光 8.5e7<br>`LGT_Strip_L` / `LGT_Strip_R` 360×5000 竖直灯带<br>`LGT_Front_Fill` / `LGT_Base_Accent` |
| 灯光可见性 | 所有灯 `visible_camera = False`：**不进入画面**，但仍参与金属反射与照明 |
| 环境 | 竖直渐变世界（下暗 → 地平线中灰 → 顶棚亮） |
| 摄影棚 | 有界深色高光地面（4 个组件倒影）+ 立在地面远边的竖直背板（ColorRamp 渐变） |
| 动画 | **无** |

> **踩过的坑（已修）**：把 MapRange 的 **float** 输出直接接到 Base Color 颜色接口，
> Blender 会把它当成**灰度**，于是背板以 0.7 灰度渲染而不是 0.01 深灰，
> 背景一片灰白。现改为经过 ColorRamp 输出真实颜色。

> **踩过的坑（已修）**：地面必须**有界**。相机仰角 22° 时地平线永远进不了画幅，
> 无限大地面会让整个背景变成一片被柔光箱照亮的光斑。现在地面在 y = -4200 截止，
> 背板立在那条边上，地面 / 背板交线落在画面中线略下方。
