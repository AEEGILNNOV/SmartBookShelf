
# Main —— 主控整合工程（速定位书格）

ESP32-S3 **N16R8** 主控固件：**两台 28BYJ-48 + ULN2003** 驱动升降/推书机构，
HUSKYLENS 2 分类识别，ILI9341 + LVGL 8.4 中文界面，
书单和机械位置用 ESP32-S3 内部 Flash（Preferences/NVS）持久化。

功能代码全部在 `lib/` 下的独立库里，`src/main.cpp` 只负责建对象、注册命令、建任务，
以及**存书/取书流程状态机**（放在 `stepperTask` 里，见第 6 节）。

```powershell
cd D:\Project\SmartBookShelf\Main
pio run -e esp32-s3-devkitc-1 -t upload
pio device monitor -e esp32-s3-devkitc-1     # 115200
```

`pio` 不在 PATH 时用绝对路径：`C:\Users\GX\.platformio\penv\Scripts\pio.exe`

> **本次改造的定位**：机械从"旧工程的三台电机"改成**两台电机（升降 + 推书）**，
> 书单规则改成**每个学科最多一本**，新增**电机调试页**、**Flash 掉电恢复**和**存书/取书流程**。
> 所有机械参数都是**待实机标定**的保守初值，在标定完成之前**不要跑自动取书/存书**。

| 改动 | 原值 | 新值 | 原因 |
| --- | --- | --- | --- |
| 电机数量 | 3 台（推出小车 / 中间夹层 / 升降平台） | **2 台**（升降 / 推书） | 本次只用两台电机；旧电机3 整个去掉 |

### 2.2.1 触摸引脚布局可以一键切换（重要）

本次改造把触摸的 5 根线从 **38/39/40/41/42** 挪到了 **48/18/13/14/38**。
**如果你的触摸模块还按旧线序接着，改完固件后触摸会完全没反应**——代码没坏，是线不对。

`config.h` 第 3.2 节给了两个选择：

| `CFG_TOUCH_PIN_LAYOUT` | 触点脚位 | 代价 |
| --- | --- | --- |
| `2`（默认） | T_CS=48 T_IRQ=18 T_CLK=13 T_DIN=14 T_DO=38 | 需要把触摸的 5 根线改接到这组脚 |
| `1` | T_CS=38 T_IRQ=39 T_CLK=40 T_DIN=41 T_DO=42（旧脚位） | 40/41/42 被触摸占用，**实体按键不能再用这三个脚** |

改成 `1` 只需要改这一个宏、重新烧录，不用动代码别处。

> 串口 `d` / `d,3` / `d,6` 现在都会打印**当前生效的触摸引脚和布局编号**，
> 接线前先敲一次，照着打印出来的 GPIO 接，就不会接错。

#### 测距引脚也已经挪走（原来"测不到"的根因）

HC-SR04 的 TRIG/ECHO 以前是 **5/6**，而 **5/6 正好在升降电机的 IN1~IN4（4,5,6,7）里面**，
两者同时接会互相干扰。所以现在测距默认走 **38/39**（空着的脚），两台电机和测距可以同时工作。

| `CFG_WAVE_PIN_LAYOUT` | TRIG | ECHO | 说明 |
| --- | --- | --- | --- |
| `2`（默认） | 38 | 39 | 和两台电机都不冲突，推荐 |
| `1` | 5 | 6 | 老脚位；**必须**同时把 `CFG_STEPPER_LIFT_ENABLE` 置 0，否则编译期报错 |

> ⚠️ **`CFG_ENABLE_WAVE` 现在是 1（开）**。它原来是 0，意味着：**不建 `waveTask`、
> 不调 `waveSensor.begin()`，TRIG/ECHO 连 `pinMode` 都没配** —— 现象就是"一直检测不到"，
> 而且串口一条测距日志都没有。这是本次"超声波一直测不到"的直接原因。
> 两个开关都开着又抢同一批 GPIO 的话，`config.h` 第 14.3 节会**在编译期直接报中文错误**。

### 2.3 电气安全（必须照做）

1. **HC-SR04 的 ECHO 是 5V 输出，不能直接接 ESP32-S3 的 GPIO**。硬件的 ECHO 线上必须做电阻分压
   （推荐 1kΩ 串联 + 2kΩ 下拉，分压后约 3.3V）或用电平转换模块。
   **把软件引脚配成 `INPUT` 并不能解决 5V 电平问题**，那只是把烧芯片的时间往后推。
2. **28BYJ-48 不要从 ESP32 的 3V3 取电**：每相约 200mA，ULN2003 同时两相通电，峰值 300mA 以上。
   独立 5V 供电，并且**必须与主控共地**，否则会出现"一走电机就复位/串口掉线"。
3. **GPIO 26~32 是封装内 Flash，GPIO 33~37 是 OPI PSRAM，绝对不能接外设**；
   GPIO22~25 在 S3 上不存在；GPIO19/20 是 USB；GPIO43/44 是 UART0。
   `config.h` 第 14.5 节有编译期体检。

### 2.4 引脚冲突的编译期体检（`config.h` 第 14 节）

| 检查 | 内容 |
| --- | --- |
| 14.1 | 同一个电机的 4 个 IN 脚不能重复 |
| 14.2 | 升降电机和推书电机不能抢 GPIO |
| 14.3 | HC-SR04 与升降电机抢脚（本工程已知冲突） |
| 14.4 | 电机与 TFT 的 6 根线抢脚 |
| 14.5 | 外设不能用 Flash/PSRAM/USB/UART0 占掉的 GPIO |
| 14.6 | HC-SR04 与触摸抢脚 |

> 这些检查只看"**同时启用**的外设"。某个外设关掉时不算占用，所以不会误报。
## 3. 任务与数据流向

| 任务 | 谁建的 | 核心 | 职责 |
| --- | --- | --- | --- |
| `recogTask` | main.cpp | 1 | **唯一**调用 HuskyLib：重连、5 秒一帧、分类 ID 防抖、投存书请求 |
| `stepperTask` | main.cpp | 1 | **唯一**碰电机引脚：消费两个命令队列、推进机械状态机、跑存书/取书流程 |
| `monitorTask` | main.cpp | 0 | 每秒采集系统信息 + 拼调试页快照（`setDebugState`） |
| `waveTask` | main.cpp | 0 | **唯一**碰 TRIG/ECHO（默认关）：5 秒一次测量、滤波、写共享快照 |
| `displayTask` | DisplayLib | 0 | **唯一**碰 LVGL：脏标志刷新、调试页出队 |
| `buttonTask` | ButtonLib | 0 | 5ms 消抖 + 事件队列 |
| `serialCmdTask` | SerialCmdLib | 0 | 轮询串口 + 执行命令队列 |

```
recogTask   --HuskyFrame-->   DisplayLib.setFrame()      (库内加锁)
recogTask   --MechRequest--> MechQueue --> stepperTask   (存书请求)
debug页按钮 --内部队列--> taskLoop -> handler -> MechQueue --> stepperTask
buttonTask  --按钮事件-->     loop() -> cli.sendCommand() -> 命令队列
monitorTask --SystemInfo-->   DisplayLib.setSystemInfo() + setDebugState()
waveTask    --WaveState-->    waveMutex 快照 --> DisplayLib.setWave()
stepperTask --mechanism.service()--> motorLift / motorPush
stepperTask --saveAllToFlash()--> StorageLib --> NVS(Flash)
```

**为什么存书/取书流程放在 `stepperTask` 里**：
`MechanismLib` 的状态变量只被"发起动作"和"推进动作"两处读写。如果发起在一个任务、
推进在另一个任务，就必须给每次访问加锁，还会出现"刚判断空闲、下一秒被占用"的竞态。
两者都放进 `stepperTask` 之后，**机械状态只有一个任务在碰**，不需要锁；
识别任务、界面、串口都只能往 `MechQueue` 投请求。

**调试页动作的安全路径**（这是本次改造专门设计的）：

```
LVGL 事件回调(displayTask) --入队--> 调试页内部队列
   -> taskLoop() 出队 -> 调 main.cpp 注册的 handleDebugCmd()
      -> 只做 xQueueSend(MechQueue)，几微秒返回
         -> stepperTask 真正执行（软限位/互斥/急停全套生效）
```

回调里**绝不**直接操作 GPIO，也绝不等待电机。

## 4. 书籍识别与分类规则

### 4.1 分类 ID 到底读哪个字段（最容易搞错的地方）

**分类标签在 `HuskyWord.id`**，也就是底层 `Result::ID`。
`HuskyLib` 在 `readFrame()` 里已经把它正确填好了：`out->id = (int16_t)res->ID;`

> ⚠️ **不要读 `Result::classID`！** `Result.h` 里 `classID` 和 `xCenter` 是**同一个 union 槽位**，
> 读它等价于读"目标中心 X 坐标"，两个字节完全一样。`HuskyWord.x` 就是那个槽位，所以也不能拿 `x` 当标签。
> 本工程不开发 OCR 关键字匹配、标题解析或 AI 分类，文字内容只用来显示。

### 4.2 学科映射表（唯一来源：`lib/BookDomainLib`）

| ID | 学科 |
| --- | --- |
| 1 | 语文 |
| 2 | 数学 |
| 3 | 英语 |
| 4 | 物理 |
| 5 | 化学 |
| 6 | 生物 |

要改学科名或加学科，只改 `BookDomain.cpp` 里的 `BOOK_NAME_TABLE`（顺带改 `BOOK_ID_MAX`）。
界面、串口日志、Flash 里的 `text` 字段、书堆顺序文本全部走 `getBookNameById()`。

### 4.3 识别节拍与防误判

| 宏 | 默认 | 说明 |
| --- | --- | --- |
| `HUSKY_READ_INTERVAL_MS` | 5000 | 正常识别周期 **5 秒**（原来是 300ms） |
| `HUSKY_RECONNECT_INTERVAL_MS` | 2000 | 掉线重试间隔（这个要快，不然用户觉得卡住） |
| `CFG_BOOK_CONFIRM_FRAMES` | 3 | 同一个分类 ID 要**连续 3 帧**都识别到才认为稳定 |

防误判的实现（`recogTask`）：

1. 读超时 / 结果数为 0 -> **清掉防抖计数**，不入库；
2. 分类 ID 不在 1~6 -> 视为无效：**不入库，也不触发任何机械动作**；
3. ID 合法但不等于上一帧 -> 防抖计数重新从 1 开始；
4. 连续稳定够 `CFG_BOOK_CONFIRM_FRAMES` 帧，而且这个 ID **没处理过** -> 投一次存书请求；
5. 已经存在书单里的学科 -> 只提示"该学科书籍已存在，未入库"，不发请求。

所以**同一帧反复到达、I2C 重连、任务重启、界面刷新都不会重复入库**。
识别到入库之间至少要等 `3 × 5 = 15 秒`，调试时可以把 `CFG_BOOK_CONFIRM_FRAMES` 改成 2。

### 4.3.1 识别到了但动态数组里没东西？敲 `j`

从"二哈看到书"到"动态数组真的多一条"，中间有 7 道关卡，任何一道没过都是"数组还是空的"：

```
1) 算法对不对        -> 必须是 分类类算法：a,2(物体分类) 或 a,3(自学习分类)
                       用物体识别/OCR 时 ID 不是 1~6，永远进不了库
2) 有没有读到帧      -> wordNum 是不是 0
3) 分类 ID 合不合法  -> 必须是 1~6
4) 防抖攒够没有      -> 要连续 CFG_BOOK_CONFIRM_FRAMES(默认3) 帧；3×5秒 = 15 秒
5) 是不是已存在      -> 方案A：同学科已在书单里就不再入库
6) 机械位置有效吗    -> 位置无效时存书请求会被拒绝！要先 g,zero 人工归零
7) 请求队列满没有    -> 满了会在下一帧自动重试
```

串口敲 `j` 会把上面 7 条的**当前值一次全打出来**，并直接指出卡在哪一步。
书单为空时敲 `i` 也会提示你去看 `j`。

> 调试阶段嫌 15 秒太慢：把 `CFG_BOOK_CONFIRM_FRAMES` 临时改成 1（看到就立刻请求）。

### 4.4 每个学科最多一本书（方案 A）

- 每个分类 ID **最多允许一条**书籍记录；
- 重复 ID **不新增、不加数量**（`count` 字段保留但**不是库存数量**）；
- 新书入库时**插到数组最顶部**（下标 0 = 书堆最顶部）；
- 取书完成后删除对应数组项，后面的自动前移；
- 从 Flash 加载时也会校验：ID 不在 1~6 丢弃、重复 ID 只留第一条。

> ⚠️ **必须承认的现实限制**：软件只能保证"书单里一个学科只有一条记录"，
> **无法阻止用户把重复学科的实体书真的放进书堆**——机械上没有"书已放入"的检测手段。
> 所以存书流程设计成"先识别/查重 -> 再把机构移到待存位 -> 提示用户放书 -> 用户按确认 -> 才写书单"，
> 如果用户在没确认的情况下自己塞了书进去，软件是不知道的，只能靠人。
> 界面和串口都会明确提示这一点，不会假装软件已经拦住了实体书。

## 5. 机械结构与步数计算

### 5.1 两台电机的职责（严格区分）

| 电机 | 机构 | 作用 |
| --- | --- | --- |
| **升降电机** | 齿轮齿条 | 带动**整叠书**上下移动，使目标书对准侧壁出书口 |
| **推书电机** | 齿轮齿条 | 带动水平推书机构，把已经对准出书口的书推出 |

> ⚠️ 升降电机**不能单独选择书堆内部的某一本书**。
> 要取第 N 本，必须先把整叠书移到"那一本对准出书口"的高度，再执行水平推出。

### 5.2 书堆顺序与位置模型

新书从顶部放入，所以**新书在逻辑书堆里位于最顶部**。数组下标 0 = 最顶部。

```
入库前:  [语文(0)] [数学(1)] [英语(2)]
入库后:  [物理(0)] [语文(1)] [数学(2)] [英语(3)]     ← 新书插到下标 0
取出下标 1（语文）后:  [物理(0)] [数学(1)] [英语(2)]  ← 后面的自动前移
```

**目标位置公式**（`calcLiftTargetForIndex()`）：

```
目标位置(相对零点) = CFG_LIFT_INDEX0_OFFSET_STEPS + 下标 × CFG_LIFT_STEPS_PER_BOOK
```

用明确的数组顺序表达书堆顺序，不用正负步数或隐式索引推算。

### 5.3 绝对步数与步数换算

| 宏 | 默认 | 含义 |
| --- | --- | --- |
| `CFG_STEPPER_WAVE_MODE` | 0 | 0 = 八拍半步（力矩大），1 = 四拍整步 |
| `STEPPER_STEPS_PER_REV` | 4096 | 28BYJ-48 输出轴一圈的步数（八拍） |
| `CFG_STEPPER_STEP_DELAY_US` | 1500 | 两步之间的延时（越小越快，太小会丢步） |
| `CFG_STEPPER_MAX_STEPS` | 8192 | 单次 `run()` 允许的最大步数 |
| `CFG_STEPPER_LIFT_RANGE_STEPS` | 4096 | 升降软限位（**待标定**） |
| `CFG_STEPPER_PUSH_RANGE_STEPS` | 2048 | 推书软限位（**待标定**） |
| `CFG_BOOK_THICK_MM` | 6.0 | 每本书的理论厚度（初始估值，仅用于粗算/显示） |
| `CFG_LIFT_STEPS_PER_MM` | 0.0 | 每毫米对应步数（**待标定**，0 = 不用） |
| `CFG_LIFT_STEPS_PER_BOOK` | 200 | **每本书对应的升降步数（主用，待标定）** |
| `CFG_LIFT_MAX_MOVE_STEPS` | 6000 | 单次自动升降的最大步数 |
| `CFG_PUSH_OUT_STEPS` | 600 | 推书行程（**待标定**） |
| `CFG_PUSH_RETRACT_STEPS` | 600 | 推书回退步数（只在 `CFG_PUSH_AUTO_RETRACT=1` 时用） |
| `CFG_PUSH_MAX_MOVE_STEPS` | 2000 | 单次自动推书的最大步数 |
| `CFG_LIFT_DIR_SIGN` / `CFG_PUSH_DIR_SIGN` | 1 / 1 | 方向符号（**必须实机点动确认**） |
| `CFG_MECH_ACTION_TIMEOUT_MS` | 30000 | 单次动作兜底超时 |

> ⚠️ **28BYJ-48 是开环控制**：没有编码器、没有限位开关。
> 堵转、失步、齿轮间隙都会让"软件以为的位置"和"机构真实位置"越差越多。
> 所以每本书步数必须是**实机标定**出来的，不是纸面算出来的。

### 5.4 软限位、互斥与急停

- **软限位**：`Stepper28BYJ::service()` 每走一步都检查 `_posSteps` 是否超出 `±rangeSteps`，
  到边立刻停并丢弃剩余步数，**绝不硬顶机构**；
- **单次上限**：`MechanismLib` 在软限位之前先查 `CFG_LIFT_MAX_MOVE_STEPS` / `CFG_PUSH_MAX_MOVE_STEPS`，
  拦住"参数多写一个 0"；
- **互斥**：`MechanismLib` 一次只允许一个轴在动。升降在动时推书请求被拒绝，反之亦然；
  重复点按钮、连续发命令都靠这一条拦下来，不会让两个目标互相覆盖；
- **急停**：`stopAll()` 立刻停两个轴、清剩余步数、释放线圈，
  并把位置标记为**无效 + 需要人工归零**；
- **线圈释放**：走完或 `stop()` 都会把四个 IN 拉低。28BYJ 停机不断电会一直发热，这是必须的。

### 5.5 动作状态机（`MechanismLib`）

```
IDLE --请求--> MOVING --走完--> DONE    --takeResult()--> IDLE
                    |
                    +--超时----> FAILED   --takeResult()--> IDLE
                    +--急停----> ESTOPPED --takeResult()--> IDLE
```

`DONE` / `FAILED` / `ESTOPPED` 是三个**必须被读走**的状态：
成功了才能改书单，失败了必须保留原记录。
任何非正常结束都会把位置判为**无效 + 需要人工归零**——
开环系统里"没走完"意味着真实位置已经不知道了。

## 6. 存书 / 取书流程

### 6.1 存书流程（`FLOW_STORE_*`）

| 步骤 | 做什么 | 失败/异常时 |
| --- | --- | --- |
| 1 | 检查系统是否空闲（有流程在跑就拒绝新请求） | 串口+调试页提示"已有流程" |
| 2 | 取得分类 ID（来自识别任务/串口 `v,s,<ID>`） | — |
| 3 | 检查 ID 是否 1~6 | 无效：**不入库、不动机械** |
| 4 | 检查该学科是否已存在 | 重复：**不新增、不加数量**，只提示 |
| 5 | 检查位置是否有效（人工归零过） | 无效：拒绝并提示先归零 |
| 6 | `markActionPending()` 先落盘，再升降到待存位 | 失败：清标记，书单不动 |
| 7 | 升降正常完成 -> `clearActionPending()` + 落盘 | 异常：保留书单，位置判无效 |
| 8 | 提示用户放书，等确认（`CFG_BOOK_PLACE_TIMEOUT_MS`，默认 60 秒） | 超时：取消入库，书单和位置都不动 |
| 9 | 用户确认（串口 `v,c` / A 键 / 调试页）-> 记录插到**数组顶部** | 写失败：提示并保持原状 |
| 10 | 保存书单 + 步数 + 位置状态到 Flash，刷新界面，打日志 | 保存失败：串口+界面都报警 |

> **为什么第 8 步要等用户确认**：机械上**没有**"书已经放入"的检测手段（没有对射开关、没有微动开关）。
> 不能虚构自动检测能力，所以把识别、确认和机械动作分开设计，用明确的状态推进。

### 6.2 取书流程（`FLOW_TAKE_*`）

| 步骤 | 做什么 | 失败/异常时 |
| --- | --- | --- |
| 1 | 检查书是否存在（下标合法 / 该 ID 在书单里） | 不存在：拒绝并提示 |
| 2 | 检查系统空闲、位置是否有效 | 无效：拒绝（**位置无效时禁止自动取书**） |
| 3 | 按目标书在数组中的下标算升降相对步数 | — |
| 4 | `markActionPending()` 先落盘，再移动升降电机，使目标书对准出书口 | 下发失败：清标记，记录保留 |
| 5 | 确认升降动作正常完成（`takeResult()`） | 异常：**保留原记录**，位置判无效，提示人工恢复 |
| 6 | 再执行推书电机动作（`movePushOut()`） | 同上 |
| 7 | 推书电机达到预设目标步数且驱动状态正常结束后，默认认为推出完成 | 异常：**保留原记录** |
| 8 | （可选）推书回退，仅在 `CFG_PUSH_AUTO_RETRACT=1` 时 | 回退失败：保留原记录 |
| 9 | **这时才**删除书籍记录，剩余书籍逻辑位置自动前移 | 删除失败：提示（机械已完成） |
| 10 | 保存书单 + 步数到 Flash，更新界面 | 保存失败：报警 |

> ⚠️ **不得在取书动作开始时就提前删除书籍记录**。升降或推书未正常完成、被急停、
> 或被软件判为异常时，都必须保留原记录，并提示用户检查机构后人工恢复。

> ⚠️ **诚实的能力边界**：没有限位开关、没有编码器、没有可靠的推出检测，
> 软件能确认的**只有"推书电机走完了预设步数"**，
> **无法证明实体书一定已经完全推出**。界面和本文档都按这个事实描述，不夸大。

> **取出一本后为什么不用改机械位置**：数组删除后，原来在下标 i+1..N-1 的书各自往前挪一格，
> 数组下标自动和真实书堆顺序保持一致。那几本书物理上并没有动（是它们上面的那本被推走了），
> 所以机械位置不需要重新计算。

## 7. Flash 持久化与断电恢复

### 7.1 用什么、存在哪

用 Arduino 框架自带的 **`Preferences`（NVS）**，写在 ESP32-S3 内部 Flash，不需要外部存储芯片。

| NVS 项 | 键 | 说明 |
| --- | --- | --- |
| 命名空间 | `sbs` | `CFG_STORAGE_NVS_NAMESPACE` |
| 数据版本 | `ver` | 改 `BookItem` 结构或存储布局时**必须 +1** |
| 书单 | `books` | `int16 条数 + N×StoredBook{id, count, text[40]}` |
| 升降步数 | `lift` | 当前累计步数 |
| 位置有效 | `posok` | bool |
| 需要归零 | `homing` | bool |
| 未完成动作 | `pend` | bool：**掉电恢复的关键** |
| 保存次数 | `scnt` | uint32 |

### 7.2 掉电恢复怎么做的（三句话）

1. **任何会改变机械位置的动作开始之前**，先调 `storage.markActionPending()` 把"未完成"写进 Flash；
2. 动作**正常完成后**，调 `clearActionPending()` 落盘，再 `saveAll()` 写新的步数；
3. 复位时如果读到 `pend = 1`，说明上次是断电中断的 -> 把位置判为**无效**，
   **要求人工归零**；在归零之前**不允许执行依赖绝对位置的自动取书**。

> ⚠️ **开机绝对不要驱动电机去找一个假定的零点**。
> 软件零点只能由调试页的"将当前位置设为零点"人工建立。

> ⚠️ **当前实现的一个诚实限制**：`Stepper28BYJ` 只有 `resetPosition()`（把位置清 0），
> 没有"写入任意步数"的接口，而用 `run()` 去补步数会**真的驱动电机**。
> 所以 `MechanismLib::restorePosition()` 只做两件事：把位置基准清 0、把位置状态置成
> "无效 + 需要人工归零"，另外把 Flash 里记的步数**读出来显示和打印**。
> 结论：**掉电后必须人工归零一次**，Flash 里的步数不会直接变成新的位置基准。
> 想要精确恢复，需要以后给 `Stepper28BYJ` 加一个只写 `_posSteps` 的 `setPosition()`。

### 7.3 写入时机（不磨损 Flash）

只在下面这些时刻写：

- 新书成功入库后；
- 取书动作正常完成后；
- 升降电机正常完成移动后；
- 人工归零后；
- 用户显式保存（`q,s` / `g,save` / 调试页"保存当前位置"）后。

**绝不每走一个步进脉冲就写一次 Flash**。
`markActionPending()` / `clearActionPending()` 各只写 1 个 bool。

### 7.4 数据损坏与重置

加载时逐条校验：

- 版本不匹配 -> **拒绝加载、不覆盖**，置 `repairNeeded` 并打日志，把决定权交给用户；
- 条数越界 / blob 长度不符 -> 判为损坏；
- `id` 不在 1~6 -> 丢弃该条并打日志；
- **重复 `id` 只保留第一条**；
- `text` 强制补 `\0` 结尾（不相信 Flash 里的内容）；
- `|liftSteps|` 超过"软限位 × `CFG_STORAGE_STEPS_TRUST_FACTOR`" -> 判不可信，要求归零。

**两个独立操作（绝不能合并成一个按钮）**：

| 操作 | 命令 | 影响 |
| --- | --- | --- |
| 清空书籍数据 | `q,c` / `c` / 调试页按钮 | **只清书单**，机械位置一点不动 |
| 位置重新归零 | `g,zero` / 调试页"设为零点" | **只重置位置**，书单调不动 |
| 全清（危险） | `q,f` | 两个都清，只有明确的"恢复出厂"才用 |

清空书籍数据需要**二次确认**（调试页按钮点第一次变成"再点一次确认清空"，3 秒不点自动取消）。

## 8. 超声波测距（HC-SR04）

### 8.1 一直测不到？按这个顺序查

| 步 | 检查 | 怎么确认 |
| --- | --- | --- |
| 0 | **`CFG_ENABLE_WAVE` 是不是 1** | 是 0 的话 `waveTask` 都不建，TRIG/ECHO 连 `pinMode` 都没配，串口不会有任何测距日志。串口敲 `u`，会直接告诉你"没启用" |
| 1 | 接线是不是 TRIG=38 / ECHO=39 | 串口 `u` 或 `d` 会打印**当前生效的 TRIG/ECHO**，照着打印出来的接 |
| 2 | ECHO 有没有**分压** | ECHO 是 5V 输出，直连 GPIO 会伤芯片。要 1k 串联 + 2k 下拉（约 3.3V）或电平转换 |
| 3 | 看错误码 | `u` 打印的 `err`：`1` = ECHO 一直没拉高（TRIG 没到 / 没供 5V / 线错）；`2` = ECHO 一直没拉低（分压不对 / 超量程） |
| 4 | 模块 5V 和共地 | HC-SR04 要 5V 供电，且**必须和主控共地** |

> ⚠️ 引脚布局可以在 `config.h` 第 8 节用 `CFG_WAVE_PIN_LAYOUT` 一键切换（1 = 5/6，2 = 38/39）。

### 8.2 实现要点

- 复用 `UltraLib` 的**非阻塞状态机**，全程不用 `pulseIn()`：TRIG 拉高 10us，
  状态机等 ECHO 上升沿/下降沿，每个等待阶段都有超时，模块没接也不会卡死任务；
- **正常测量周期 5 秒**（`WAVE_MEASURE_INTERVAL_MS=5000`，原来是 100ms）；
- 检查超时、无回波、超量程和明显异常值：
  - 错误码 `1` = ECHO 一直没拉高（查 TRIG / 模块 5V）；
  - 错误码 `2` = ECHO 一直没拉低（查分压 / 是否超量程）；
  - 超出 `CFG_WAVE_MIN_MM`~`CFG_WAVE_MAX_MM` 判无效；
- 复用现有滤波：滑动平均窗口 `CFG_WAVE_FILTER_N=5`；
- 另有跳变检查 `CFG_WAVE_JUMP_MM=80`：和上次有效值差太多就不采纳，防止多路径反射直接改变状态；
- **无效读数不覆盖有效值，也绝不触发任何自动机械动作**；
- 超声波距离和升降累计步数**分开保存**，不把估算距离当绝对位置；
- 界面（第 4 页测距页）显示当前距离、有效性和错误状态，调试页也显示；
- 串口 `u` 系列提供诊断信息。

> **不要**把 HC-SR04 当成能分辨每次 6mm 位移的高精度尺子。它只用来辅助观察书堆位置和机械状态。
> 取书后要回到待存书位置时，优先用**已经标定的步数**控制，超声波只做辅助校验。
> `CFG_MECH_USE_WAVE_CHECK` 默认 0（关）：传感器的安装几何关系和固定目标距离都还没确认，
> 盲目用距离判"书到位了"会引入假阳性。等实机标定完再打开。

## 9. 调试界面（第 6 页）与人工归零

### 9.1 怎么进入（**实体按键优先，不依赖触摸屏**）

| 方式 | 操作 | 需要触摸吗 |
| --- | --- | --- |
| **实体按键** | **按键1 长按 = 进调试页；再长按一次 = 退出**（切回状态页） | 不需要 |
| **实体按键（备用）** | 按键3 长按 = 进/出调试页（有些板子 GPIO0 不好按，所以留了两个入口） | 不需要 |
| 实体按键 | 按键1 短按 = 下一页（一路翻到第 6 页也行） | 不需要 |
| 串口 | `g` 进入 / 状态页用 `n` 翻页 | 不需要 |
| 触摸按钮 | 状态页、书列表页右下角的「调试」按钮 | **需要触摸** |
| 自动 | 识别到有效分类并请求入库时自动跳到调试页 | 不需要 |

退出：实体按键长按（同上）、触摸页上的「返回」按钮、或串口 `g` 之后再翻页。
打开或关闭调试页**不会自动驱动电机**，也**不额外占用任何 GPIO**。

> ⚠️ **触摸不好用/没接线时，调试页的全部操作都能用实体按键或串口完成**——
> 见 9.5 节。这是本次专门补的，因为原来调试页的按钮全是 LVGL 触摸按钮，
> 触摸一断调试页就变成"只能看不能动"。

### 9.2 调试页能看到什么

- 位置是否有效、**是否需要人工归零**（醒目提示）；
- 升降电机：累计步数、剩余步数、软限位、是否在走；
- 推书电机：最近一次动作步数、是否在走；
- 测距：最近距离 mm、是否有效、错误码；
- 书单条数 + 逻辑书堆顺序；
- 上一次动作是否正常完成、失败原因（中文）；
- Flash 是否已保存；
- 当前点动步长。

### 9.3 调试页按钮（**这些是触摸按钮；不接触摸请直接看 9.5 节**）

| 按钮 | 作用 |
| --- | --- |
| 升降上移 / 下移 | 按当前步长点动升降 |
| 推书前进 / 后退 | 按当前步长点动推书（后退需要机械真的支持） |
| 停止 | 急停（一行红色，醒目） |
| 小10 / 中100 / 大500 | 切换单次点动步长 |
| 设为零点 | **人工归零**（见 9.4） |
| 保存位置 | 立刻把当前书单+步数+位置状态写进 Flash |
| 清空书籍 | **二次确认**：第一次点文字变成"再点一次确认清空"，3 秒不点自动取消 |
| 返回 | 回到状态页 |

> ⚠️ **点动步长上限**：`CFG_DEBUG_JOG_SMALL/MID/LARGE` = 10 / 100 / 500，
> 点动还要同时过"单次上限"和"软限位"两道关，超了会被夹短或直接拒绝（串口会打印原因）。
> 「清空书籍」和「设为零点」是**两个独立按钮**，永远不能合并。

### 9.4 怎么人工归零

> ⚠️ **没有限位开关，所以本次采用人工归零，不实现虚假的自动寻零**。

1. 用「小10」步长点动升降，确认**方向对不对**（不对就改 `CFG_LIFT_DIR_SIGN`）；
   - 触摸：点调试页的「升降上移 / 下移」按钮；
   - **不接触摸**：按键4 升降点动 / 按键5 推书点动，按键1 长按切步长；或串口 `g,up` / `g,down`；
2. 逐渐换「中100」，把机械平台移动到你认可的**参考位置**（比如最顶那本书正对出书口）；
3. 点「设为零点」；**不接触摸**就按**按键3**，或串口 `g,zero`；
4. 软件把当前步数设为 0，把位置状态设为**有效**，并立刻保存到 Flash；
5. 串口会打印 `机械: 人工归零完成` 和提示。

> ⚠️ **清零软件步数 != 电机已经自动移动到机械原点**。电机其实一点没动，
> 界面和串口都会明确写这一句。

> **急停/超时/异常终止之后**（`v` 里的状态变成 4/5/6）不能继续往下走，
> 位置会被自动判为无效，需要重新评估，**不能无条件把不完整动作的结果当可靠位置**。
> 点「停止」也不代表电机准确停在原目标位置。

### 9.5 没有触摸屏时怎么用调试页

触摸屏没接、或者线序不对的时候，**调试页的全部功能都可以用实体按键或串口完成**：

| 想做的事 | 实体按键 | 串口 |
| --- | --- | --- |
| 进/出调试页 | 按键1 长按（或按键3 长按） | `g` 进入；`n` 翻页 |

## 10. 页面与滑动规则

**所有界面只允许上下滑动，禁止左右滑动**：

- 页面切换用 `DisplayLib::setPage()` / `nextPage()`（**只认按钮和串口命令**）；
- 根屏幕 `lv_scr_act()` 的 `LV_OBJ_FLAG_SCROLLABLE` 被清除，**根屏幕完全不滚动**；
- 书列表页和调试页的容器都显式 `lv_obj_set_scroll_dir(..., LV_DIR_VER)`；
- 行控件/按钮/标签都清掉自身滚动，手指拖动交给父容器；
- **没有任何水平拖动切页手势**——水平滑动不会进任何其它页面；
- 所有 `lv_*` 调用只在 `displayTask` 里做；业务任务只写数据（`setDebugState` 等）；
- 触摸不可用时，全部功能仍可通过串口命令使用。

| 页 | 内容 |
| --- | --- |
| 0 状态页 | 二哈连接/算法/识别块/书单条数 + 「调试」入口 |
| 1 系统信息页 | RAM/PSRAM/Flash/运行时间 |
| 2 书列表页 | 学科名 + 逻辑顺序 + 条数，每行一个「取出」按钮（走取书流程） |
| 3 超声波测距页 | 距离/滤波/统计/测厚 |
| 4 触摸测试页 | 按钮计数 + 坐标/原始值 |
| 5 **电机调试页** | 见第 9 节 |

> 主界面有清晰的存书、取书和调试入口：调试走「调试」按钮，
> 存书走串口 `v,s,<ID>`（或按键 A），取书走书列表页的「取出」按钮（或按键 B）。

## 15. 已知限制与还没做的事

1. **机械参数全部未标定**（第 12 节）。标定之前自动取书/存书不应该跑。
2. **开环控制**：没有编码器/限位开关，软件只知道"发了多少步"，不知道机构真的走到了哪。
3. **没有"书已放入/已取出"的检测**：存书要用户按确认，取书只以"推书电机走完预设步数"为准，
   **无法证明实体书已经完全推出**。
4. **掉电后不能自动恢复位置**：`Stepper28BYJ` 没有"写入任意步数"的接口，
   开机盲动又是禁止的，所以必须人工归零一次。要精确恢复需给 `Stepper28BYJ` 加 `setPosition()`。
5. **HC-SR04 与升降电机抢 GPIO5/6**，默认关测距；要同时用必须挪引脚（第 2.2 节）。
6. **按键 3 = GPIO0 是 BOOT 脚**，复位时按住会进下载模式；按键 40/41/42 与摄像头 D5/D6/D7 冲突（本次不用摄像头）。
7. **字库缺少量 ASCII/标点**（`>` `、` `“”` `…` `—`），显示层做了替换兜底；
   要保留原字符需重新生成 `src/ui_font_16.c`（见 `fontgen/README.md`）。
8. **`count` 字段语义**：为了兼容旧结构保留了它，但**不是库存数量**（每个学科最多一本）。
9. **没有做真实断电试验**，掉电恢复链路只做了代码级和编译级验证。
10. **旧的三台电机设计已废弃**：`CFG_STEPPER_M3_ENABLE` 硬关，防止残留旧代码去驱动不存在的电机。

## 16. 快速上手（实机第一次上电）

```text
1. 不接电机，先上电看串口和屏幕
   -> 应该看到 BOOT_DONE、机械参数、以及"⚠️ 机械位置无效: 自动取书已被禁止"

2. 二哈切到分类算法:  a,2   (物体分类)   或  a,3 (自学习分类)
   把书对着二哈，串口会打印 识别: 分类 ID=n -> 学科名

3. 接电机（独立 5V + 共地！），进调试页:  g
   用小10步长点动，确认方向和机构没问题

4. 标定: 按 README 第 12 节的顺序，改 config.h 里对应参数，重新烧录

5. 标定完，点[设为零点] -> 扇区位置变有效
   然后试一次手动:  v,s,2  (存数学) -> 放书 -> v,c  (确认)
                     v,t,0  (取最上面那本)

6. 断电重启，看串口:
   - 正常保存过 -> "存储: 已恢复 N 本书"
   - 上次动作没走完 -> "需要人工归零"，这是对的，不是 bug
```

## 17. 屏幕没内容怎么查（原有排错手段，全部保留）

显示这条链一共四层，任何一层断了都是"屏上什么都没有"：

```
① 供电/背光/接线/SPI 引脚/屏驱动型号   <- TFT_eSPI 直接画彩条就能证明
② LVGL 刷屏链路(tick / draw buffer / flush_cb / 字节序)
③ 界面控件(页面/标题栏/底色)          <- 这些不经过字体
④ 字体(汉字字形/压缩解压)             <- 只影响"文字"，不会让整屏空白
```

```powershell
pio run -e screen-raw  -t upload   # 只画彩条，完全不初始化 LVGL
pio run -e screen-lvgl -t upload   # 彩条 + LVGL 纯色块（不碰任何字体）
pio run -e screen-log  -t upload   # 正常界面 + 刷屏日志 + LVGL 日志
```

串口 `d` / `d,1` / `d,2` / `d,4` / `d,5` 的判读表见这两条命令的帮助输出。
